# 用户管理服务
* 支持用户通过gitee、github登陆
* 支持通过手机号方式直接登陆，自动实名
* 通过gitee、github登陆方式属于未实名用户，可以手动绑定手机号，完成实名认证
* 通过不同的方式登陆算作不同的user，因为增加一个userDelegate服务，支持账号之间的授权
* 支持未登陆、已登陆、已登陆已实名用户访问，具体业务逻辑中会处理
* 个人项目，生产环境为2核2G的云服务器，用户量较少，暂时认为够用，必要时我会将mysql、redis这种依赖专门部署服务器
* 补充：这里说的登陆包括注册和注册后登陆

# 切面
* 编写一个切面，用在接口上，判断用户是否有权限访问，切面参数可以设置三种用户level
* 创建一个BaseRequest，通过切面自动注入用户信息
* BaseRequest除了包括用户基本的id等信息外，还包括被授权的user、是否实名

# 登陆机制
* 使用jwt
* accessToken有效期为2小时，refreshToken有效期为90天
* 支持配置化
* refreshToken要让前端使用安全存储(onlyHttp之类)

# 账户管理
* 支持修改账户基本信息

# 用户间授权
* 支持用户向某个用户请求授权、或者请求被授权
* 支持用户接受某个用户的授权、被授权，并持久化
* 授权可以拒绝、可以取消

# 配置化
* 支持配置化热更新，代码里面不要出现魔鬼数字、字符等

# mysql表
* 一个user表，记录账号基本信息、登陆渠道(gitee、github、手机)、绑定手机号
* 一个user_delegate表
* 一个全局数据配置表，或者使用使用@ConfigurationProperties + @RefreshScope特性专门写个配置类(推荐)

# redis
* 要存储的数据的key你来定义
* 相关查询可以考虑使用缓存加速

# 限流与日志
* 验证码获取限流
* 其他你认为有必要加限流的
* 记录用户访问量，输出到日志中
