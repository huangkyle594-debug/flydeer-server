# 00-项目概要

> 基于当前仓库代码梳理。技术栈：JDK 21 · Spring Boot 3.5 · Maven 多模块 · MyBatis · PageHelper · MySQL · Redis（已接入，业务侧暂未深度使用）。

---

## 1. 项目目录结构

```
flydeer-server/
├── bash/                          # 本地 / 云服务器启动与工具脚本
│   ├── run.sh                     # Compose + 本地 jar 一键启动
│   ├── run-server.sh              # 无 Docker 的服务器启动
│   ├── mybatis-generate.sh         # MyBatis Generator
│   └── .run/                      # 运行期 pid / 日志（gitignore）
├── doc/
│   ├── sql/                       # 建表 DDL
│   ├── input/                     # 需求输入（人工维护）
│   └── generate/                  # 本目录：由代码梳理生成的文档
├── flydeer-common/    # 公共工具、异常、常量
├── flydeer-contract/  # 跨模块契约：DTO / 枚举 / API 接口
├── flydeer-repository/# MyBatis Entity / Mapper / Repository
├── flydeer-service/   # 可复用领域服务（短信、OAuth、JWT、用户）
├── flydeer-api/       # 用例编排（对接 contract API）
├── flydeer-controller/# HTTP Boot 应用（端口 8080）
├── compose.yaml                   # 本地 MySQL + Redis + app
├── pom.xml                        # 父 POM
└── README.md
```

模块内部惯例包名：`com.flydeer.<module>...`。

可运行入口：

| 应用 | 主类 | 默认端口 |
|---|---|---|
| HTTP API | `ControllerApplication` | `8080` |

Spring 装配链：`ControllerApplication` → `@Import(ApiApplication)` → `ServiceApplication` → `RepositoryApplication`（`@MapperScan`）。

## 2. 模块划分与职责

```
common  ←  contract  ←  repository  ←  service  ←  api  ←  controller  (HTTP)
```

| 模块 | Artifact | 职责 |
|---|---|---|
| **common** | `flydeer-common` | 统一异常体系、错误码常量、校验/文本/IP/手机号工具、认证等级枚举 |
| **contract** | `flydeer-contract` | 对外契约：`ApiRequest` / `ApiResult`、用户相关 Request/VO、枚举、`AuthorizationApi` / `UserMangeApi` / `UserDelegateApi` |
| **repository** | `flydeer-repository` | MyBatis Entity/Mapper/XML、Repository 封装、MapStruct Entity↔DTO、应用侧 ID 生成 |
| **service** | `flydeer-service` | 短信验证、OAuth、JWT、限流（Caffeine）、用户/委托领域逻辑；持有 Redis / JWT / 阿里云短信依赖 |
| **api** | `flydeer-api` | 用例编排，实现 contract 中的 API 接口，组装 VO |
| **controller** | `flydeer-controller` | REST Controller、`@AuthCheck` 参数解析、Cookie 工具、全局异常处理、Actuator |

依赖规则：

- 只允许上层依赖下层，禁止反向依赖（例如 repository 不得依赖 service）。
- controller 只依赖 api。
- 跨模块共享类型放在 contract / common，避免在上层直接暴露 Entity。

## 4. 可配置化内容

配置主文件：`flydeer-controller/src/main/resources/application.yml`（共享默认值）。  
按环境使用 Spring Profile，**不再使用 `.env`**：

| Profile | 配置文件 | 用途 |
|---|---|---|
| `dev`（默认） | `application.yml` + `application-dev.yml`（gitignore） | 本机开发；密钥放 dev 覆盖 |
| `docker` | `application-docker.yml` | Compose 内网（`mysql` / `redis` 主机名） |
| `prod` | `application-prod.yml`（gitignore，从 `.example` 复制） | 云服务器 / 生产 |
| `test` | `src/test/resources/application-test.yml` | 单元 / 集成测试（H2） |

模板：`application-dev.yml.example`、`application-prod.yml.example`。

### 4.1 基础设施

| 配置项 | YAML 路径 | 默认（dev） |
|---|---|---|
| 数据源 | `spring.datasource.*` | `localhost:3306/flydeer`，用户/密码 `flydeer` |
| Redis | `spring.data.redis.*` | `localhost:6379` |
| HTTP 端口 | `server.port` | `8080` |
| Docker Compose 集成 | `spring.docker.compose.enabled` | `false` |

## 5. 热更新方式

当前项目提供以下几层「变更生效」能力，按场景选用：

### 5.1 开发期：Spring Boot DevTools

- `spring-boot-devtools` 声明在 **api** 模块（runtime），controller 依赖 api，故 IDE / `./mvnw spring-boot:run` 开发时可触发 classpath 变更后的自动重启。
- `./bash/run.sh` / `run-server.sh` 启动的是 **已打包 jar**，DevTools 重启链路通常不生效；改代码后需重新构建再启动。

### 5.2 配置热刷新：Actuator `/actuator/refresh`

- 多处 `@ConfigurationProperties` 标注了 `@RefreshScope`（如 JWT、短信、限流、OAuth、ID 生成等）。
- 修改外部配置源后，可调用：

```bash
curl -X POST http://localhost:8080/actuator/refresh
```

- 仅刷新绑定到 RefreshScope 的 Bean；**不会**热替换已发出的 JWT、已写入的 Cookie，也不等于完整热部署业务代码。
- 仓库未内置 Spring Cloud Config Server；以 `application-{profile}.yml` 为主，`refresh` 适合后续接配置中心时使用。

### 5.3 进程级重启（本地 / 服务器）

```bash
# 本地（Compose + jar）
./bash/run.sh stop && ./bash/run.sh

# 云服务器（无 Docker）
./bash/run-server.sh restart
./bash/run-server.sh --skip-build   # 已有 jar 时跳过编译
```

日志与 PID：`bash/.run/`。

### 5.4 建议

| 变更类型 | 推荐方式 |
|---|---|
| Java 业务代码 | 重新 `./mvnw package`（或 IDE 运行）后重启进程 |
| 可 `@RefreshScope` 的配置项 | 改配置 → `POST /actuator/refresh`（确认 Bean 已绑定成功） |
| DDL / Mapper 生成 | 改表 → `./bash/mybatis-generate.sh` → 编译重启 |
| 密钥类配置（JWT secret、OAuth secret） | 改后必须重启；并评估已有 Token 是否失效 |
