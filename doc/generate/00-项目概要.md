# 00-项目概要

> 基于当前仓库代码梳理。技术栈：JDK 21 · Spring Boot 3.5 · Maven 多模块 · MyBatis · PageHelper · MySQL · Redis（已接入，业务侧暂未深度使用）。

---

## 1. 项目目录结构

```
flydeer-struct-mind-server/
├── bash/                          # 本地 / 云服务器启动与工具脚本
│   ├── run.sh                     # Compose + 本地 jar 一键启动
│   ├── run-server.sh              # 无 Docker 的服务器启动
│   ├── mybatis-generate.sh         # MyBatis Generator
│   └── .run/                      # 运行期 pid / 日志（gitignore）
├── doc/
│   ├── sql/                       # 建表 DDL
│   ├── input/                     # 需求输入（人工维护）
│   └── generate/                  # 本目录：由代码梳理生成的文档
├── flydeer-struct-mind-common/    # 公共工具、异常、常量
├── flydeer-struct-mind-contract/  # 跨模块契约：DTO / 枚举 / API 接口
├── flydeer-struct-mind-repository/# MyBatis Entity / Mapper / Repository
├── flydeer-struct-mind-service/   # 可复用领域服务（短信、OAuth、JWT、用户）
├── flydeer-struct-mind-api/       # 用例编排（对接 contract API）
├── flydeer-struct-mind-controller/# HTTP Boot 应用（端口 8080）
├── flydeer-struct-mind-task/      # 定时任务 Boot 应用（端口 8081）
├── compose.yaml                   # 本地 MySQL
├── .env.example                   # 环境变量模板
├── pom.xml                        # 父 POM
└── README.md
```

模块内部惯例包名：`com.flydeer.structmind.<module>...`。

可运行入口：

| 应用 | 主类 | 默认端口 |
|---|---|---|
| HTTP API | `ControllerApplication` | `8080`（`SERVER_PORT`） |
| Task | `TaskApplication` | `8081`（`TASK_SERVER_PORT`） |

Spring 装配链：`ControllerApplication` → `@Import(ApiApplication)` → `ServiceApplication` → `RepositoryApplication`（`@MapperScan`）。

## 2. 模块划分与职责

```
common  ←  contract  ←  repository  ←  service  ←  api  ←  controller  (HTTP)
                                    ↘
                                      task  (定时任务，不依赖 api)
```

| 模块 | Artifact | 职责 |
|---|---|---|
| **common** | `flydeer-struct-mind-common` | 统一异常体系、错误码常量、校验/文本/IP/手机号工具、认证等级枚举 |
| **contract** | `flydeer-struct-mind-contract` | 对外契约：`ApiRequest` / `ApiResult`、用户相关 Request/VO、枚举、`AuthorizationApi` / `UserMangeApi` / `UserDelegateApi` |
| **repository** | `flydeer-struct-mind-repository` | MyBatis Entity/Mapper/XML、Repository 封装、MapStruct Entity↔DTO、应用侧 ID 生成 |
| **service** | `flydeer-struct-mind-service` | 短信验证、OAuth、JWT、限流（Caffeine）、用户/委托领域逻辑；持有 Redis / JWT / 阿里云短信依赖 |
| **api** | `flydeer-struct-mind-api` | 用例编排，实现 contract 中的 API 接口，组装 VO |
| **controller** | `flydeer-struct-mind-controller` | REST Controller、`@AuthCheck` 参数解析、Cookie 工具、全局异常处理、Actuator |
| **task** | `flydeer-struct-mind-task` | 独立 Boot 进程，依赖 service（当前业务任务较空，骨架已就绪） |

依赖规则：

- 只允许上层依赖下层，禁止反向依赖（例如 repository 不得依赖 service）。
- controller 只依赖 api；task 只依赖 service，不走 api。
- 跨模块共享类型放在 contract / common，避免在上层直接暴露 Entity。

## 4. 可配置化内容

配置主文件：`flydeer-struct-mind-controller/src/main/resources/application.yml`。  
本地 / 服务器可用环境变量或 `.env`（`run-server.sh` 会 `source`）覆盖。

### 4.1 基础设施

| 配置项 | 环境变量 | 默认值 |
|---|---|---|
| 数据源 URL | `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_DATABASE` | `localhost:3306/struct_mind` |
| 数据源账号 | `MYSQL_USER` / `MYSQL_PASSWORD` | `struct_mind` / `struct_mind` |
| Redis | `REDIS_HOST` / `REDIS_PORT` | `localhost:6379` |
| HTTP 端口 | `SERVER_PORT` | `8080` |
| Task 端口 | `TASK_SERVER_PORT` | `8081` |
| Docker Compose 集成 | `spring.docker.compose.enabled` | `false`（脚本也会显式关闭） |

### 4.2 认证与 JWT

| 配置项 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `app.jwt.secret` | `AUTH_JWT_SECRET` | 内置占位串 | **生产必须替换** |
| `app.jwt.access-token-ttl` | `AUTH_ACCESS_TTL` | `2h` | Access Token 有效期 |
| `app.jwt.refresh-token-ttl` | `AUTH_REFRESH_TTL` | `90d` | Refresh Token / Cookie 有效期 |
| Refresh Cookie 名 / Secure / Path | `AUTH_REFRESH_COOKIE*` 等 | `refresh_token` / `false` / `/api/v1/auth` | yml 中部分键缩进在 `app` 下，实际绑定以 `JwtTokenConfig` 默认值兜底 |
| 前端 OAuth 回调页 | `AUTH_FRONTEND_REDIRECT` | `http://localhost:3000/auth/callback` | OAuth 成功后 302，并带 `accessToken` |

### 4.3 短信

| 配置项 | 环境变量 | 默认值 |
|---|---|---|
| Mock 开关 | `SMS_MOCK_ENABLED` | `true` |
| AccessKey / Secret | `SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET` | 空 |
| 签名 / 模板 | `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE` | 空 |
| Region / Endpoint | `SMS_REGION` / `SMS_ENDPOINT` | `cn-shanghai` / `dypnsapi.aliyuncs.com` |
| 国家码 | `SMS_COUNTRY_CODE` | `86` |

### 4.4 限流

| 配置项 | 环境变量 | 默认值 |
|---|---|---|
| 同手机号发送间隔 | `SMS_INTERVAL` | `60s` |
| 手机号日上限 | `SMS_DAILY_PHONE` | `20` |
| IP 日上限 | `SMS_DAILY_IP` | `50` |
| 登录间隔 | `LOGIN_INTERVAL` | `1s` |

> 实现为进程内 Caffeine；多实例部署时各实例独立计数。

### 4.5 OAuth

`app.oauth.gitee.*` / `app.oauth.github.*`：

- `client-id` / `client-secret` / `redirect-uri`
- `authorize-url` / `token-url` / `user-url` / `scope`

环境变量示例：`OAUTH_GITEE_CLIENT_ID`、`OAUTH_GITHUB_CLIENT_SECRET` 等。

### 4.6 用户 ID 生成

| 配置项 | 环境变量 | 默认值 |
|---|---|---|
| 起始 ID | `ID_START` | `10000000` |
| 步长随机范围 | `ID_STEP_MIN` / `ID_STEP_MAX` | `1` / `99` |

`user_info.id` 由应用分配，不是数据库自增。

### 4.7 Actuator / 日志

- 暴露端点：`health`、`info`、`refresh`
- 业务包日志级别：`com.flydeer.structmind=DEBUG`（可按环境调低）

## 5. 热更新方式

当前项目提供以下几层「变更生效」能力，按场景选用：

### 5.1 开发期：Spring Boot DevTools

- `spring-boot-devtools` 声明在 **api** 模块（runtime），controller 依赖 api，故 IDE / `./mvnw spring-boot:run` 开发时可触发 classpath 变更后的自动重启。
- `./bash/run.sh` / `run-server.sh` 启动的是 **已打包 jar**，DevTools 重启链路通常不生效；改代码后需重新构建再启动。

### 5.2 配置热刷新：Actuator `/actuator/refresh`

- 多处 `@ConfigurationProperties` 标注了 `@RefreshScope`（如 JWT、短信、限流、OAuth、ID 生成等）。
- 修改外部配置源后，可调用：

```bash
curl -X POST http://localhost:8080/actuator/refresh
```

- 仅刷新绑定到 RefreshScope 的 Bean；**不会**热替换已发出的 JWT、已写入的 Cookie，也不等于完整热部署业务代码。
- 仓库未内置 Spring Cloud Config Server；本地仍以 yml / 环境变量为主，`refresh` 适合后续接配置中心时使用。

### 5.3 进程级重启（本地 / 服务器）

```bash
# 本地（Compose + jar）
./bash/run.sh stop && ./bash/run.sh
./bash/run.sh --with-task

# 云服务器（无 Docker）
./bash/run-server.sh restart
./bash/run-server.sh --skip-build   # 已有 jar 时跳过编译
```

日志与 PID：`bash/.run/`。

### 5.4 建议

| 变更类型 | 推荐方式 |
|---|---|
| Java 业务代码 | 重新 `./mvnw package`（或 IDE 运行）后重启进程 |
| 可 `@RefreshScope` 的配置项 | 改配置 → `POST /actuator/refresh`（确认 Bean 已绑定成功） |
| DDL / Mapper 生成 | 改表 → `./bash/mybatis-generate.sh` → 编译重启 |
| 密钥类配置（JWT secret、OAuth secret） | 改后必须重启；并评估已有 Token 是否失效 |
